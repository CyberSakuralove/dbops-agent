# DBOps Agent：成本感知的运维 Agent 与可验证安全处置评测

告警出现后，系统是否真的坏了、是否正在自行恢复、应该等待还是介入？本项目用可复现的 SQLite 故障环境研究这些选择，并把授权、重试和结果验证交给确定性代码。LLM 负责调查和处置规划；执行器负责权限与事务，判分器核验实际状态。

目前交付了五个故障回归、独立审批接口、持久幂等执行器、字段保护与变更见证，以及一组索引同步配对环境。真实模型实验和 PostgreSQL 锁语义核验尚未完成。

## 快速运行：全部免费

Python >= 3.11，在本目录执行：

```powershell
python -m pip install -e ".[dev]"
python -m scripts.smoke
python -m scripts.audit_shortcuts
python -m scripts.pair_bench
python -m scripts.validate
ruff check dbops_agent scripts tests
```

`smoke` 先检查五个故障的损坏态、空操作、正确脚本、护栏和 trace，再运行自动化回归。`audit_shortcuts` 对旧漏洞做修复后复现，写入 `docs/audit-results-after.json`。`pair_bench` 运行规则基线，写入 `docs/pair-results.json`，不会调用模型。

安装依赖会访问包仓库，上述三个实验不会调用模型 API。工具数据、监控与事故均为合成样本。

## 可以直接展示的工程内容

1. **从反例修评测。** 原版检查通过，但金额篡改、执行失败重试和跨上下文重复执行存在漏洞。保留旧证据与修复后证据，避免把“测试绿了”当成可靠性证明。
2. **独立授权与可恢复执行。** L1 申请只返回 `request_id`；批准与拒绝在操作者接口进行。审批、业务效果、操作结果和审计在同一个 SQLite 事务中提交。实测子进程中断和并发重试。
3. **比较取证和干预成本。** 两个世界初始业务状态相同，后台同步分别推进和停滞。安全重建在两个世界都可以通过；比较实际改写行数、诊断次数和逻辑完成时间，不人为制造“健康世界重建就失败”的结论。

这些是当前工程和实验设计的亮点。规则可能比 LLM 更好；目前没有真实模型增益数字。

## 当前离线结果

环境和完整口径见 [验证报告](docs/验证报告.md)。以下均为脚本与合成 SQLite 环境的结果。

| 漏洞或检查 | 修改前 | 修改后 |
|---|---|---|
| 从参数推导的未申请确认令牌 | 接受 | 无法授权 |
| 合法支付金额被后端改坏 | 判分通过 | 判分失败 |
| 重建上下文后同键重试 | 重复执行一次 | 重复副作用为 0，返回原结果 |
| 执行失败后同键重试 | 假报成功 | 仍返回实际失败，键未占用 |
| 固定三种盲修 | 3/5 通过 | 1/5 通过 |
| 不读监控的业务扫描规则 | 5/5 通过 | 仍为 5/5 |

最后一项是保留的评测局限：固定五场景不能证明监控必要，也不能证明 LLM 比规则强。它们作为功能回归单列，不与配对实验合并成一个“成功率”。

配对实验包含四个配置，每个配置有推进、停滞两个世界，共八个模拟实例：

| 策略 | 正确且满足截止时间 | Agent 插入的索引行数合计 | 完成 tick 合计 |
|---|---|---|---|
| 盲目重建 | 8/8 | 234 | 24 |
| 初始业务快照规则 | 8/8 | 234 | 32 |
| 等待后复查规则 | 8/8 | 117 | 44 |
| 监控规则 | 8/8 | 141 | 35 |
| 同工具权限的 LLM | 待测 | 待测 | 待测 |

等待规则在这组实例上减少了改写，但用了更多时间；监控滞后的实例中，监控规则会采取保守重建。这些是预先固定的少量模拟配置，不是广泛泛化或生产性能证据。tick 是环境逻辑时间，改写行数也不是人民币损失。

## 独立审批演示

先创建一个不会覆盖旧证据的演示目录，并申请支付去重：

```powershell
python -m scripts.demo init
python -m scripts.demo request
python -m scripts.approve --db runs/demo/business.db
```

`request` 返回申请 ID，但不删除支付行。在独立操作者终端核对动作和参数后批准，或者把 `approve` 换成 `deny`：

```powershell
python -m scripts.approve --db runs/demo/business.db --request <request_id> --decision approve --actor engineer --reason "已核对重复支付行"
python -m scripts.demo execute --request <request_id>
python -m scripts.demo judge
```

用同一个申请再次 `execute`，会返回已存结果，不重复执行。审批默认有效期 300 秒；过期可重新 `request`。需要重新演示时选择新的 `--dir`，不会自动删除之前的记录。

`ApprovalService` 不在 Agent 工具注册表内。自动化测试和漏洞对照中的批准来自**独立测试角色的模拟决策**，没有真人介入。操作者能够访问数据库，属于信任边界；当前方案隔离的是模型的工具权限，没有给任意本地 Python 程序建立 OS 沙箱。

## 执行与判分边界

- 所有数据库写操作必须有稳定的幂等键，逻辑操作按“事故 ID + 键”标识；同键换动作或参数会拒绝。
- 审批绑定事故、动作、规范化参数、幂等键、相关资源版本和有效期，并且消费一次。相关资源改动后又恢复原值也会使旧审批失效；无关审计或配置写入不会使支付去重审批失效。
- 已完成的同一操作先查持久结果，再核验审批，避免提交后丢失响应时因审批已消费而无法重试。执行失败或提交前崩溃不会消耗审批或保存成功结果。
- 查询使用只读连接、表和函数白名单、结果上限与 SQL 指令限额。审批、操作、审计、资源版本和变更见证元数据不可通过 Agent SQL 读取。
- 判分独立读取前态快照、合法字段、索引完整内容和数据库变更见证。金额和关联关系被改坏、瞬时改坏再恢复、漏记执行日志、重复副作用，都有反向测试。申请审批和被拦截的调用不等同于实际损害。
- 原子性只覆盖同一 SQLite 数据库。Markdown 报告限制在 `workspace/reports` 并用临时文件替换；它不在数据库事务里，不宣称跨文件或外部 API 的 exactly-once。
- SQLite 会话表模拟阻塞关系，不代表已经实现真实 PostgreSQL 锁等待、事务回滚或生产自愈。哈希链能检测留存记录被改动，不能防止掌握整个文件的操作者重算一条链。

## 代码入口

| 文件 | 职责 |
|---|---|
| `dbops_agent/guard/policy.py` | 动作分级、参数白名单和上限 |
| `dbops_agent/guard/execution.py` | 审批状态机、持久幂等与事务提交 |
| `dbops_agent/tools/library.py` | 只读观测、有限修复、报告工具 |
| `dbops_agent/judge/protection.py` | 前态、字段保护、变更见证与独立校验 |
| `dbops_agent/incident/index_pair.py` | 时间推进、后台同步、统一工具与成本统计 |
| `dbops_agent/runtimes/bare_loop.py` | 模型调查循环与独立审批回调 |
| `tests/` | 安全、进程中断、并发、配对和运行时反向测试 |

业务与执行元数据同库是为了本地事务原子性；观测接口实施读权限隔离。评测快照在模型不可读的 fixture 根目录，配对环境的隐藏运行事实只用于推动环境，不传入模型提示词或重建工具。

五场景运行器默认逐项人工决策；付费实验的 API Key 通过环境变量设置，不进 Git：

```powershell
python -m scripts.pilot --limit 2 --seeds 1 --budget 3 --approval-mode manual
python -m scripts.pair_bench --llm --budget 3 --out runs/pair-llm.json
```

`simulated-approve`、`simulated-deny` 是显式实验选项，运行清单会记录审批模式。种子仅为试次标签，目前没有发送给 provider；本地 cassette 回放不产生新 provider token 或费用，不能作为新的独立模型试次。换模型前需配置 API 兼容性与价格。

token 按每次模型响应记一次，避免多个工具调用重复累计；每次事故的估计花费独立统计。现有定价、峰谷折扣和汇率是历史本地假设，没有在本轮核实，费用不是 provider 账单。预算在响应后依据估计费用熔断，不能保证服务商账单严格不超过指定金额；真实实验前需重新核对价格，并在服务商侧设限。
